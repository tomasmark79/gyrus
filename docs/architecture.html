NixonCpp / C++20 / architecture

One library, multiple target platforms

The application assembles services through UtilsFactory and passes their context to the library. The same sources build for native platforms and WebAssembly.

Where to start with your application

Change application behavior in src/app/Application.cpp. Add reusable logic to src/lib/ and public headers to include/. Utility services compile into the same library; the context holds their interfaces, and the library takes its logger and asset manager from that context.

Tests and build boundaries

tests/meson.build registers GoogleTest tests for AssetManager, ConsoleLogger and FileReader. Meson includes them only in native builds when build_tests allows tests and the dependencies are available. The public library header currently also includes the internal UtilsFactory.hpp.
